# Installer Visual Studio Code et ouvrir votre dossier de travail

Relier l'éditeur de code à votre arborescence Ce workshop s'appuie directement sur les concepts fondamentaux que vous avez étudiés dans les activités précédentes. Vous avez exploré le métier de développeur, la notion de programme et, surtout, la manière dont l'ordinateur organise le travail via des fichiers et des dossiers, ainsi que les chemins d'accès et l'arborescence. Un éditeur de code, comme Visual Studio Code, n'est pas un simple traitement de texte. C'est l'outil principal du développeur, conçu pour comprendre la syntaxe des langages de programmation, gérer des projets structurés en dossiers et faciliter l'écriture du code. Le modèle mental clé ici est le suivant : l'éditeur est la fenêtre de travail qui vous permet de visualiser et de manipuler l'arborescence de dossiers que vous avez créée pour votre formation. Il devient le point central depuis lequel vous écrirez, organisererez et exécuterez vos futurs programmes. Une erreur fréquente pour les débutants est de vouloir ouvrir des fichiers individuels dans l'éditeur sans d'abord ouvrir le dossier racine de leur projet. Cette approche prive l'éditeur de la vue d'ensemble du contexte du projet et peut compliquer la navigation. Un autre écueil est de mal identifier le chemin d'accès au dossier de travail, ce qui empêche de l'ouvrir correctement depuis l'éditeur. Par exemple, si votre dossier de travail est nommé `formation_fullstack` et se trouve directement sur votre bureau, le chemin absolu pourrait ressembler à `C:\Users\VotreNom\Bureau\formation_fullstack` sur Windows ou `/Users/VotreNom/Bureau/formation_fullstack` sur macOS.
