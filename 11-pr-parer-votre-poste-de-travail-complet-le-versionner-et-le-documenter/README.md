# Préparer votre poste de travail complet, le versionner et le documenter

Rappel : outils, dépôt et versions Votre poste de développeur repose sur quelques outils : un éditeur de code et son terminal intégré, un navigateur capable d'afficher le code source d'une page, et Git. Un dépôt Git est un dossier dont Git suit l'historique grâce à un dossier caché nommé .git. Un commit est un instantané validé de vos fichiers. Il est accompagné d'un auteur, d'une date et d'un message. Retenez le modèle en trois zones. Le répertoire de travail est l'endroit où vous modifiez vos fichiers. La zone d'index reçoit ce que git add prépare. L'historique conserve ce que git commit enregistre, et git status vous indique à tout moment l'état de chaque fichier. Plusieurs erreurs sont fréquentes. Si vous oubliez de configurer votre nom et votre e-mail, vos commits sont mal attribués. Un message vague comme « modifs » ne dit rien du contenu du commit. Les noms de dossiers avec des espaces sont pénibles à taper dans le terminal, et Git ne suit pas les dossiers vides, seulement les fichiers. Prenons un exemple chiffré. Votre dépôt compte 3 commits, puis vous modifiez 2 fichiers mais n'en ajoutez qu'un avec git add. Après git commit, l'historique compte 4 commits et git status signale encore 1 fichier modifié non indexé. Votre répertoire n'est propre que lorsque git status répond qu'il n'y a rien à valider.
