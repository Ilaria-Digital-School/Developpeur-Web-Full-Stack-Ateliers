# Enregistrer trois versions de votre dossier et relire leur historique

Rappel théorique : Git, l'historique de votre travail Git est un système de contrôle de version distribué, essentiel pour suivre l'évolution de votre code. Imaginez-le comme une machine à remonter le temps pour votre dossier de travail. Chaque enregistrement, appelé commit, capture un instantané précis des fichiers, accompagné d'un message décrivant les modifications. La branche principale, souvent nommée main ou master, sert de ligne temporelle pour ces instantanés. Le modèle mental clé est celui du dépôt, un stockage organisé de l'historique. Votre espace de travail contient les fichiers actifs. La zone de staging (l'index) est l'antichambre où vous préparez les fichiers à figurer dans le prochain instantané. Les erreurs fréquentes incluent des messages de commit vagues comme "fix" qui rendent l'historique inutilisable, ou l'oubli d'ajouter des fichiers avant de valider, laissant une capture incomplète. Pour illustrer, supposons que vous modifiez un fichier `projet.txt`. Vous exécutez `git add projet.txt` pour le placer dans la zone de staging, puis `git commit -m "Ajout de la section contact dans le document principal` pour créer un point de restauration définitif, identifié par une empreinte unique (hash). Cette opération crée un nœud dans l'historique de votre dépôt Git. Préparation de votre environnement de travail Pour démarrer cet atelier, vous devez être positionné dans le dossier de votre projet, hébergeant le dépôt Git que vous avez initialisé lors des activités précédentes. Vérifiez que vous êtes bien à l'emplacement correct. Ce dossier doit contenir vos fichiers de travail, comme ceux de votre boutique en ligne ou d'autres...
