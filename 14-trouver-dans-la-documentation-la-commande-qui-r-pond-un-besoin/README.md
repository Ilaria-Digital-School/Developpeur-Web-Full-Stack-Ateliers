# Trouver dans la documentation la commande qui répond à un besoin

Rappel théorique sur la recherche de documentation Les développeurs professionnels passent une partie significative de leur temps à consulter la documentation plutôt qu'à écrire du code. Il n'est pas nécessaire de tout mémoriser. L'objectif est de savoir où et comment chercher l'information lorsque vous en avez besoin. Le modèle mental clé consiste à considérer la documentation comme votre premier réflexe, avant un forum ou un collègue. La plupart des environnements en ligne de commande, comme le terminal bash sous Linux ou macOS, ou PowerShell sous Windows, disposent d'un système d'aide intégré, souvent accessible via la commande `man` (pour manual). Une erreur fréquente est de consulter la documentation en surface, sans lire attentivement les options ou les exemples fournis. Une autre erreur est de se fier à une seule source d'information. Croisez toujours vos sources. Un exemple chiffré : pour vérifier la version de Python installée, la commande `python --version` est communément utilisée. Cependant, sur certains systèmes où Python 2 et Python 3 coexistent, il peut être nécessaire d'utiliser `python3 --version`. Sans lire la documentation spécifique à votre système ou les messages d'aide (`python --help`), vous pourriez exécuter la mauvaise commande et obtenir un résultat incorrect ou une erreur. Ce mini-exemple illustre l'importance de lire les détails. Vous avez précédemment appris à chercher des réponses efficacement en utilisant la documentation, les forums et les assistants d'IA.
