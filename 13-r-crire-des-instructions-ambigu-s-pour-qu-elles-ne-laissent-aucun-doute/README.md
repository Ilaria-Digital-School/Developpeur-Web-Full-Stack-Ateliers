# Réécrire des instructions ambiguës pour qu'elles ne laissent aucun doute

Rappel théorique et fondement de l'exercice Dans le développement logiciel, la capacité à écrire des instructions non ambiguës, aussi appelées spécifications, est une compétence fondamentale. Une instruction est ambiguë lorsqu'elle permet plusieurs interprétations ou ne définit pas clairement le contexte, le point de départ, l'action précise à accomplir, ou l'état final vérifiable. Ce flou peut être une source majeure de bugs, de retards et de conflits dans une équipe. Le modèle mental clé à adopter est que vous communiquez avec une machine ou un collègue aussi littéral que possible. Il ne peut pas deviner. Il ne peut pas choisir entre deux options si vous ne lui donnez pas de critères. Votre rôle est donc de supprimer toute forme de subjectivité, de généralité et d'imprécision. Vous devez explicitement définir toutes les informations nécessaires pour que la tâche soit exécutée sans poser de question. Les erreurs fréquentes incluent l'utilisation de termes subjectifs comme « mieux », « plus rapide », « joli » sans mesure objective, l'omission des conditions initiales (« depuis où ? ») ou du périmètre (« jusqu'où ? »), et la description d'un résultat qui n'est pas observable. Une instruction comme « Optimiser la base de données » est trop vague. Elle ne dit pas quel aspect de la base de données doit être optimisé, par quelle méthode, ni quel résultat quantifié constitue une amélioration.
