# Atelier : bouton alert avec gestionnaire d’événement

RAPPEL THÉORIQUE Jusqu'ici, vous avez manipulé des variables, des fonctions et vu un aperçu des événements du navigateur. Il est temps de relier ces briques. Un événement est une action de l'utilisateur (clic, survol, saisie clavier) que le navigateur détecte. Pour y réagir, on attache un gestionnaire d'événement (event listener) à un élément HTML. Le mental model est simple : « Quand cet élément subit cet événement, alors exécute cette fonction ». La méthode standard est addEventListener('click', maFonction). On récupère d'abord l'élément avec document.getElementById('monId') ou document.querySelector('.maClasse'), puis on lui greffe l'écouteur. Erreurs fréquentes à éviter : appeler la fonction avec des parenthèses dans addEventListener (btn.addEventListener('click', direBonjour()) exécute la fonction immédiatement au lieu de l'attacher — il faut passer la référence direBonjour sans parenthèses) ; oublier que le script s'exécute avant le chargement du DOM (placez votre avant la fermeture de ou utilisez l'événement DOMContentLoaded) ; se tromper d'identifiant entre le HTML et le JS. Mini-exemple : const bouton = document.getElementById('salut'); bouton.addEventListener('click', () => { alert('Bonjour !'); }); Ce code affiche une boîte d'alerte à chaque clic. Vous réutilisez ici les fonctions fléchées vues précédemment. Gardez en tête cette logique élément → événement → fonction, elle est au cœur de toute interface web interactive.
