# Adapter votre page d'accueil aux écrans de téléphone

Rappel théorique et contexte Le développement web responsive repose sur un principe fondamental : une seule base de code HTML et CSS doit s'adapter automatiquement aux différentes tailles d'écran. L'approche mobile-first, souvent recommandée, consiste à concevoir d'abord pour les petits écrans avant d'ajouter des améliorations pour les écrans larges. Cette méthode présente plusieurs avantages, notamment la priorisation des contenus essentiels et des performances souvent meilleures. Le modèle mental à adopter est celui de la fluidité. Vos éléments ne doivent plus avoir des dimensions fixes en pixels, mais utiliser des unités relatives comme les pourcentages, les « vw » (viewport width) ou les « rem ». Les grilles CSS (Grid) et les boîtes flexibles (Flexbox) s'adaptent naturellement à cette logique lorsqu'elles sont configurées avec des valeurs flexibles comme « fr » ou « auto ». Les erreurs fréquentes sont nombreuses. On retrouve souvent l'oubli de la balise viewport dans l'en-tête HTML, qui permet au navigateur mobile d'ajuster la largeur de la page. Une autre erreur classique est l'utilisation de largeurs (width) fixes en pixels pour les conteneurs principaux, ce qui crée un défilement horizontal indésirable sur mobile. Enfin, les points de rupture (breakpoints) mal choisis, basés sur des appareils spécifiques plutôt que sur le contenu lui-même, conduisent à une maintenance difficile. Prenons un mini-exemple chiffré. Sans CSS responsive, un conteneur « div » défini avec « width: 960px » dépassera de l'écran d'un téléphone moderne (largeur typique de 375px).
