# Mini-checkpoint - Préparer un café

**Rappel théorique** Un algorithme est une suite finie, ordonnée et non ambiguë d'instructions permettant de résoudre un problème ou d'accomplir une tâche. Chaque instruction doit être précise, atomique (non décomposable en sous-étapes implicites) et placée dans le bon ordre. On parle de flux d'exécution linéaire lorsque les instructions s'exécutent les unes après les autres, de haut en bas, sans branchement conditionnel ni boucle. Le pseudo-code est une façon d'écrire un algorithme en langage naturel structuré, lisible par un humain, indépendamment de tout langage de programmation. Il sert de pont entre l'intention et le code réel. Un organigramme, lui, représente visuellement ce même enchaînement d'étapes via des formes géométriques standardisées (rectangle pour une action, losange pour une condition, ovale pour début/fin). Erreurs fréquentes à éviter : oublier des préconditions (ex. : vérifier qu'il y a de l'eau avant de lancer la machine), regrouper plusieurs actions en une seule étape floue (ex. : "faire le café" sans décomposer), et ne pas respecter l'ordre logique des opérations. Mini-exemple : pour "allumer son ordinateur", on n'écrit pas juste "démarrer l'ordi". On écrit : (1) Appuyer sur le bouton d'alimentation, (2) Attendre l'écran de connexion, (3) Saisir le mot de passe, (4) Valider. Chaque étape est claire, unique et ordonnée. --- **Énoncé de l'atelier** Dans ce mini-checkpoint, vous allez mobiliser tout ce que vous avez appris sur le séquençage, le pseudo-code, les organigrammes et les bonnes pratiques de clarté et de granularité.
